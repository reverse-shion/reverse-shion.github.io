## 1. 実装概要

入口：`tarot-breaker-3d/prototype/index.html`。

GAME START → 1000年前の星界の回廊 → シオンの一人称で歩行 → 光の会話地点へ接近 → 「ふたりと話す」 → 既存の3人スキット → 表情切替 → 「会話を終える」 → 同じ位置・視点へ復帰 → 再移動・再会話。

仮エリアは12×18単位。リュミエールの間周辺を想起させる床、境界の低い欄干、2本の柱、閉じた扉、歩行の目安になる床の線、背景の静止した星、会話地点の光で構成する。正式な建築・地理の確定ではない。人物の3D化はせず、シオンは位置・衝突円・眼高1.6の一人称プレイヤー、しおぽん・リュミエールは既存会話素材で登場する。光は人物の代用モデルではなくイベントマーカー。

v0.3の完成MVP全域より小さくした理由は、1エリアで「歩く・会話する・戻る」を短時間で反復検証するため。植物、水、王宮、戦闘、探索報酬、保存、別マップ、現代、ルーム本体への接続は含めない。

## 2. 使用技術

- 静的HTML/CSS/ES Modules。ビルド工程、バックエンド、API、DBなし。
- Three.js **0.180.0 / r180** の配布ファイル2本を同じバージョンで同梱。CDN実行依存なし。MITライセンス・由来・SHA-256を同梱。
- WebGL 2必須。設計対象はiOS/iPadOS Safari 16.4以上と現行Android Chrome／PCブラウザ。これは対象方針であり、最低OSの実機保証ではない。
- Pointer Eventsによる左スティック＋右ドラッグ。PCはWASD／矢印、ドラッグ、E。左右ポインターを分離。
- 視点は一人称、上下角を制限し、揺れ・慣性・自動回転なし。
- Node.js 24.19.0、jsdom 26.1.0、Python 3.12.14で補助検証。

Three.jsはPhase 1推奨と静的ESM構造に合い、今回必要な描画のみで成立するため採用した。Babylon.jsへの変更や独自WebGL実装を比較試作する必要はないと判断した。r180は取得可能な固定版として採用し、最新版との優劣を主張しない。[Three.js公式ドキュメント](https://threejs.org/docs/)

## 6. B — コード上確認結果

- 会話中は3D入力と描画ループを停止。位置・yaw・pitchを保存し、退出時に復元。
- 1つのアプリがRAF・イベント・音を所有する。会話開始の重複を状態で拒否。
- 毎回独立した派生エンジンを用い、古いfetchをAbortControllerで中断。タイムアウト・404・途中退出から復帰可能。
- 会話終了／途中戻る／上部閉じる／Escape／タブ中断を同じ後始末へ集約。
- モーダル中の背景をinert化し、Tabのフォーカスを会話内に維持。退出後は3Dへフォーカスを戻す。
- Safe Area、100dvh、46px以上の主要操作、横画面での会話配置調整。最適な画面方向の決定は実機後。
- WebGL context lossで停止、復旧後に明示再開。復旧しない場合の再読込案内。
- 新規保存・音設定保存・API・DB・アカウントなし。

## 7. C — 外部ブラウザ検証状況

クラウドブラウザには接続できた。ローカル検証画面 `http://127.0.0.1:8765/` への遷移は `ERR_BLOCKED_BY_CLIENT` で拒否。URLポリシーによる環境制約として扱い、実装を停止しなかった。

ローカルHeadless Chromiumは未インストール。補助的な取得を試したが配布サーバーへの要求が30秒でタイムアウトし、試行全体を55秒で終了した。環境修復に作業を拡大していない。

外部開発用URLで起動画面の表示とGAME START操作、ESM/Three.js/JSON読込まで確認した。その先の3D起動は、クラウドブラウザの `GL_VENDOR = Disabled, GL_RENDERER = Disabled` により `Error creating WebGL context` で停止した。ブラウザ側でWebGLが無効であるという具体的な証拠が得られた。保護やブラウザ設定の変更は行わない。

3D描画・歩行・一連の復帰と音の聴取は **外部ブラウザ／実機検証待ち**。3Dを偽の2Dへ置き換えず、スキット単独の実表示確認用に `prototype/tests/skit-smoke.html` を追加し、3D検証と明確に分離した。

## 10. 音声

音源はAudioControllerに1個だけ所有させる。3Dとスキットで別音源を作らず、探索volume=0.34／会話volume=0.18に変更する。ユーザーの操作で任意ON、会話中もOFF可能。visibilitychange/blur/pagehide、破棄、再生Promise拒否を扱う。

SEはPhase 2に採用していない。会話の表情・文字送りも無音のため、SE重複を発生させる登録はない。「実SE再生が検証済み」とはしない。ルーム本体を同時表示しないため、既存ルーム独自BGMとの併存もない。実音量・ループ継ぎ目・iOSの復帰後再生は実機待ち。

## 11. キャッシュ

Phase 1で確認されたルートSWの2重install/activate/fetch、相互キャッシュ削除、欠損precacheは未修正。試作から登録解除・Cache API削除・新規SW登録を行わない。

独自JS/CSS/JSONと共有スキットJS/CSS/JSON/表情/音源を `v=p2-1.1.0` で参照。内部importにも版を付け、Three.jsはバージョン付きディレクトリで固定。SWが有効でも旧URLと同一キャッシュキーになりにくい構成にしたが、古いHTML自体・既存登録状態・実配信先の挙動は別途確認が必要。

開発用プレビューが別オリジンの場合、公式サイトで過去に登録されたSWの検証にはならない。本番反映前には既存SWあり／なし両方で、JS・CSS・JSON・画像・音声の更新とOFF/ONを確認する。ネット切断時に公式トップがfallbackされる等の既存挙動も本番相当確認の対象。

既存エンジンの変更は保存名の任意無効化と例外fallbackのみだが、共有ファイルであるため、将来マージ前に既存スキットページのスモーク確認も必要。

## 14. 将来アプリ化への影響

ストーリーJSON・キャラクター・状態・描画・UI・入力・音を分離し、同梱資産と相対参照で動作する。バックエンドやGitHub Pages独自APIには依存しない。将来WebView等へ持ち込む際の不必要な固定依存を避けた。

ただし、ネイティブ性能、WebViewメディア制限、配布・決済・審査・ストア用ライフサイクル・オフライン品質は未検証。アプリ化可能性の保証やストア対応完了を意味しない。

## 15. Phase 3判定・停止点

**HOLD — VALIDATION HOLD。Phase 3には進まない。**

実装・自動検証・スキット単独のブラウザ確認は完了しているが、3Dの実表示・スマホ操作・実音・性能の重要確認が残る。ローカルURL制限とクラウドブラウザのWebGL無効化はENVIRONMENT HOLDの要因として記録し、方式そのもののNO-GOやコード上のTECHNICAL HOLDと混同しない。ユーザーがWebGL有効な端末で開けるプレビューを用意できたため、次の判断を止めている主因はVALIDATION HOLDとする。

GO／GO WITH CONDITIONSへの変更には外部ブラウザと実機で一連の体験を確認し、必要な修正・条件を記録する。次にユーザーが確認するのはPhase 2の動作であり、mainマージ・本番反映・Phase 3開始はそれぞれ別の明示判断とする。
